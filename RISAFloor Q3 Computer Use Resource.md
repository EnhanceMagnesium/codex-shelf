# RISAFloor Q3 computer-use resource

Use this resource for the embedded Q.3 (LMS Question 4) in the assignment supplied in this repository. Treat the assignment and lectures as evidence. Read the current Codex computer-use tool documentation and applicable skills in the active session before interacting with the app. Follow that environment's supported UI APIs and permissions. Do not assume a menu exists or use screen coordinates from a different version.

## Establish the working session

1. Inspect the running application and determine RISAFloor version, ES availability, licensing or demo limitations, units, and whether the currently open model contains user work. Preserve existing models. Start a fresh blank model for this assignment and save to a new work folder if the edition allows it.
2. Read `Q3 assignment crop.png` and the assignment PDF in `Cole S Q3 RISA Handoff.zip`. Check the plan directly. It has 5 by 4 column gridlines, 20 column positions, four horizontal bays marked 5.0 and three vertical bays marked 6.0. The marks have no printed units. Explicitly adopt and record units, column/edge offsets, slab geometry, floor elevation and supports. The drawn slab extends beyond the outer column centerlines.
3. Record assumption values and their rationale for slab thickness, f′c, fy, unit weight, office live load, column dimensions and height, supports, number of stories, edge conditions, design code and all omitted data. The assigned superimposed dead load is 75 psf. Treat program slab self-weight separately so it is counted once. Do not import parameters or results from historical models.

## Operate and verify

4. Build a concrete floor slab in RISAFloor ES, add the full grid and 20 columns, and define material, section, slab, load cases, combinations, support lines and design strips required by the actual version. After each set of edits, inspect the current UI state and verify fields, units, layout and connectivity. Use only controls actually visible or documented in the active tool. Capture views of model geometry, properties and loading.
5. Run the analysis and concrete slab design. Read warnings and resolve model errors; do not silently omit failures. Record actual combination names and verify that strength and service checks use appropriate combinations. If the model is revised, rerun and preserve evidence from the final model state.
6. Capture or export slab moment and shear results, support-line/design-strip results, positive and negative reinforcement by direction and strip, punching shear, service deflections, column forces/reactions, code checks and the warning log when available. Include units, directions, location, combination, result tables and legends. Legend extrema alone do not establish strip design values. Verify equilibrium and load totals where possible.
7. Create an editable Excel column design using the model's actual column axial forces and moments. Include representative interior, edge and corner cases when supported by the outputs and identify governing combinations. Show section assumptions, bar arrangement, equations, substitutions, units, applicable strength factors, interaction/axial checks and detailing. Reconcile software code edition with the older course method. Clearly state unresolved checks.
8. Save the native model and Excel workbook when supported, plus exports and screenshots to a new working folder. Update a progress log with current model state, assumptions, verified results, pending work and precise next action. If demo restrictions prevent saving, keep the session open while exporting all available inputs and results, record the restriction and preserve recovery instructions. Never imply a model was saved or analyzed without evidence.

The user requested calculations first and to stop before rendering a solution PDF. Q1 and Q2 are outside this task. Do not claim completion without actual RISAFloor outputs and the Excel design. If the software or a specific input is unavailable, complete independent preparation, preserve work and state exactly what remains.
